四、优先级 P1：成员 A 接入训练好的情感分类模型
------------------------------------------------------------
优先级：最高
负责人：成员 A
建议分支：

git checkout -b feature/model-integration

任务目标：
让系统真正使用课程知识点中的 TF-IDF + Logistic Regression 模型，而不是只用规则判断情感。

具体步骤：

1. 训练模型：

python -m src.train_model --data data/processed/bilingual_reviews_train.csv --model-dir models

2. 确认生成模型文件：

models/sentiment_model.pkl
models/tfidf_vectorizer.pkl

3. 修改 src/nlp_analyzer.py：

目标逻辑：

如果模型文件存在：
    使用 tfidf_vectorizer 转换文本
    使用 sentiment_model 预测 positive / neutral / negative
    输出模型预测结果和置信度
否则：
    使用原来的规则情感分析兜底

4. 页面中最好能体现：
   - 情感倾向
   - 置信度
   - 使用方式：模型预测 / 规则兜底

涉及文件：
src/nlp_analyzer.py
src/train_model.py
app.py

完成标准：
1. 训练模型后，单条分析页面优先使用模型结果。
2. 删除模型文件或没有模型文件时，系统仍能使用规则兜底。
3. 单元测试通过：

python -m unittest discover -s tests

4. Streamlit 页面正常运行。


五、优先级 P1：成员 B 接入大模型 API
------------------------------------------------------------
优先级：最高
负责人：成员 B
建议分支：

git checkout -b feature/llm-client

任务目标：
让系统可以基于 NLP 结构化结果生成自然语言总结和改进建议。

具体步骤：

1. 本地创建 .env 文件：

LLM_API_KEY=自己的 API Key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat

注意：
.env 不能提交到 GitHub。
API Key 不能写进代码。

2. 查看并完善 src/llm_client.py。

重点优化两个函数：
   - build_single_review_prompt()
   - generate_review_advice()

3. 单条评价 Prompt 需要包含：
   - 原始评价文本
   - 语言类型
   - 情感倾向
   - 主题类别
   - 关键词

4. 输出建议保持 JSON 格式：

{
  "summary": "...",
  "problems": ["..."],
  "suggestions": ["..."],
  "risk_level": "low/middle/high"
}

5. 保留本地兜底：
如果 API 失败，系统仍然输出 local_fallback。

涉及文件：
src/llm_client.py
.env.example
docs/bilingual_upgrade_plan.md

完成标准：
1. 单条中文评价能生成总结建议。
2. 单条英文评价能生成总结建议。
3. API 失败时，本地兜底仍能生成结果。
4. 不提交 .env。
