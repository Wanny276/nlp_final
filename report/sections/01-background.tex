\section{项目背景}

\subsection{课程评价分析需求}

课程评价是教师了解教学效果的重要来源。
学生在评价中通常会同时谈到教师讲解、课程内容、作业量、考试范围、实验环境和学习收获。
例如“老师讲得很清楚，但是作业太多”既包含积极反馈，也指出了具体问题。
如果只统计评分或简单匹配正负词，系统很容易忽略转折关系和问题发生的位置。

教育文本分析相关研究指出，开放性反馈适合从整体情感、句子情感、实体和方面等层次分析；
方面级情感分析在教育场景中的价值，在于帮助教师区分学生对课程内容、授课方式、作业或考核等对象的态度
\citep{shaik2023educational,hajrizi2020aspect}。
基于这一思路，本项目输出积极、中性、消极三类情感标签；
同时保留课程维度、关键词和原文证据，便于教师复核系统判断。

面向课程评价这一具体任务，现有处理方式主要有以下困难：

\begin{itemize}
  \item \textbf{评价数量集中。}期末集中收集评价时，教师和课程负责人难以逐条阅读并归纳。
  \item \textbf{表达形式复杂。}评价可能是中文、英文或中英混合文本；
        也可能包含缩写、拼写错误、否定、建议和讽刺等非规范表达。
  \item \textbf{情感与问题维度不等价。}同一句话整体上可能是中性；
        但在作业任务或考试安排上包含明确的消极反馈。
        仅输出情感标签，不足以支持教学改进。
  \item \textbf{结果需要可解释。}教学场景不能只给出“消极”结论；
        还应说明命中了哪个课程维度、原文依据是什么，以及应优先处理什么问题。
\end{itemize}

因此，本项目将非结构化课程评价转换为结构化信息。
输出内容包括语言、情感倾向、置信度、课程维度、关键词、证据片段和教学改进建议。
系统目标不是替代教师判断，而是减少人工整理成本，并为后续复核提供清晰线索。

\subsection{使用场景与目标用户}

系统主要面向三类使用者：

\begin{enumerate}
  \item \textbf{任课教师：}分析单条典型评价，了解学生认可点和具体困难；
        辅助调整教学节奏、作业量和实验安排。
  \item \textbf{课程负责人：}批量导入课程评价 CSV，查看情感分布、课程维度分布和高频关键词；
        识别需要优先处理的共性问题。
  \item \textbf{教学管理人员：}通过统一的结构化指标比较不同课程或不同学期的反馈趋势；
        同时保留可追溯的原文证据。
\end{enumerate}

典型使用流程为：教师上传评价数据；
系统进行双语预处理和情感分类；
再按照教学内容、授课方式、作业任务、考试安排、实验实践、学习收获六个维度定位问题；
最后生成便于教师阅读和复核的总结建议。

\subsection{项目目标与边界}

本项目构建的是一个可运行、可解释、可降级的 NLP 辅助系统。
具体目标如下：

\begin{itemize}
  \item 支持中文、英文和中英混合课程评价；
  \item 完成积极、中性、消极三分类，并处理常见混合评价；
  \item 将评价映射到课程维度，同时展示命中关键词和原文证据；
  \item 支持首页概览、单条分析、批量分析、固定案例验证和模型评估展示；
  \item 在 BERT、本地传统模型或外部 API 不可用时保持主要流程可运行；
  \item 提供可复现的数据处理、模型训练、消融实验和压力测试脚本。
\end{itemize}

项目在设计阶段区分三类结果。
独立测试集用于比较模型性能；
固定案例用于验证演示流程；
独立压力测试用于观察复杂表达下的鲁棒性。
三类结果分别呈现，避免将固定案例上的满分解释为系统整体准确率。

在上述目标基础上，本项目实现了一个面向课程评价的 NLP 应用原型。
系统支持单条评价分析、批量 CSV 分析、固定案例验证和模型评估；
并将情感倾向、课程维度、关键词、原文证据和教学建议组织为统一输出。
具体模型指标、消融实验和压力测试结果将在后文实验部分展开说明。
