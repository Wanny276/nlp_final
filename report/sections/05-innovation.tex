\section{项目特色与创新设计}

本项目的设计重点不在于简单堆叠模型。
课程评价的实际难点是混合表达、噪声文本、证据复核和部署环境不稳定。
因此，本节将项目特色概括为三点：
分层混合情感分析、原文证据保留机制和证据约束的建议生成。
长文本滑动窗口和独立压力测试作为这些设计的实现支撑和评估证据，不单独拔高为创新点。

\subsection{分层混合情感分析}

项目没有将“使用 BERT”本身作为创新点。
系统针对课程评价的真实表达方式设计分层混合流程：
BERT 负责主要上下文语义判断；
规则模块处理课程场景中可明确描述的转折、否定、建议和混合评价；
TF-IDF Logistic Regression 与纯规则模型承担自动回退。
不同方法承担各自适合的任务，而不是简单投票。

该流程还包含长文本滑动窗口推理。
系统没有直接截断超过 160 Token 的评价；
而是使用带重叠的窗口，并按每个窗口的有效 Token 数加权聚合概率。
后端会记录窗口数量、Token 数和截断标志。
这部分设计主要用于减少长评价信息丢失，并为后续界面提示保留数据基础。

固定案例消融结果显示，完整流程在 12 条固定案例上通过 12/12。
该结果只说明课堂演示流程能够稳定跑通。
由于固定案例中包含较多典型表达，项目没有把它当作整体模型结论；
而是另外使用 48 条独立压力测试观察复杂输入下的鲁棒性。

\subsection{原文证据保留机制}

多数文本清洗流程会直接修改整个输入。
如果后续证据片段也基于清洗文本生成，教师看到的证据就可能与学生原话不一致。
本项目将“用于分类的标准化文本”和“用于展示与证据的原始文本”分开。
缩写展开、重复字母收缩和拼写纠错只进入情感分类通道；
课程维度、关键词和证据仍从原文产生。

同时，纠错策略限制在情感词范围内；
并要求极小编辑距离与唯一候选。
这样可以降低误改课程名、编程库名称或合法英文词形的风险。
教师可以从系统输出回到学生原话，判断系统是否正确理解了“作业任务”“考试安排”或“实验实践”等具体维度。

\subsection{证据约束的建议生成}

系统把大语言模型限制在“表达与归纳”环节，而不是让它直接决定情感和课程问题。
提示词要求建议中的问题维度优先来自已识别的课程维度；
证据必须引用原始评论或主题证据。
即使 LLM 不可用，本地模板也会输出相同字段。
这种结构降低了生成式模型幻觉对核心分析结论的影响。

从课程项目角度看，本项目的主要价值在于将情感分类、规则校正、
证据保留、模型回退和建议生成组织成一个较完整的应用流程。
独立压力测试包含 48 条样本，每类 6 条；
覆盖缩写、拼写错误、否定、讽刺、隐含抱怨、中英混合、长文本和混合情感。
完整混合流程通过 34/48 条样本，Accuracy 为 0.7083，Macro-F1 为 0.7217；
在这组构造困难样本上高于 rule-only、TF-IDF-only 和 BERT-only 三个单独模块。

同时，压力测试也暴露出系统边界。
讽刺类别仅通过 1/6，隐含抱怨仅通过 3/6，
说明有限规则和当前训练数据还不足以稳定处理复杂语用现象。
因此，本项目不将压力测试结果解释为真实场景准确率，
而是将其作为发现失败类型和确定后续改进方向的依据。
